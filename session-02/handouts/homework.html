بخش الف — منوی شروع رنگی

  1. قبل از شروع بازی، یک منو نشان بده: 
    ⚔  Quiz Battle  ⚔
۱) بازی جدید
۲) خروج
    منو رنگی باشد — مثلاً گزینه‌ی بازی سبز و گزینه‌ی خروج قرمز.
  2. بازی فقط با انتخاب ۱ شروع شود. با ۲ خداحافظی کند و تمام شود.
    اگر کاربر چیز دیگری زد، برنامه نباید بمیرد — یک پیام زرد بدهد و دوباره منو را نشان دهد.
  3. ⭐ اگر توانستی: بعد از تمام‌شدن بازی، برگردد به منو تا بشود دوباره بازی کرد.

بخش ب — عضله‌ی commit 💪

  1. کار بالا را در حداقل ۵ commit جدا انجام بده — نه یک commit بزرگ آخر شب.
    هر تغییر کوچکِ کارکننده = یک commit. مثلاً: «منو را نشان بده» → commit، «خروج را اضافه کن» → commit، «ورودی اشتباه را مدیریت کن» → commit. 
    git add .
git commit -m "Add colored start menu"
  2. آخرش اسکرین‌شات این دستور را بگیر و بیاور: 
    git log --oneline
    یادت باشد: صفحه با کلید q بسته می‌شود، ترمینال هنگ نکرده.
  3. یک‌بار عمداً فایلت را خراب کن، ذخیره کن، و با این دستور برش گردان: 
    git restore game.py
    این را انجام بده حتی اگر لازمش نداری — دستت باید عادت کند.
قبل از تحویل، چک کن
  • منو رنگی است و با ۲ برنامه تمام می‌شود
  • ورودی اشتباه، برنامه را نمی‌کشد
  • git log --oneline حداقل ۵ خط با پیام معنادار نشان می‌دهد
  • در git status هیچ اثری از پوشه‌ی venv نیست
  • پروژه در C:\dev\... است، نه Desktop و نه OneDrive
⭐ اختیاری — عضله‌ی راه‌اندازی
یک پوشه‌ی کاملاً جدید بساز، فقط game.py و requirements.txt را داخلش کپی کن، و پروژه را از صفر راه بینداز: 
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python game.py
هفته‌های بعد این چهار خط را ده‌ها بار می‌زنی. بگذار دستت عادت کند.
🔮 برای جلسه‌ی بعد
هفته‌ی بعد سنگین‌ترین و مهم‌ترین جلسه‌ی فنی دوره است: بازی از تک‌نفره تبدیل می‌شود به دونفره. آخر آن جلسه، اولین مسابقه‌ی واقعی‌ات را با هم‌تیمی‌ات بازی می‌کنی. پس پروژه‌ات باید سالم و commit شده باشد.
