# کیت جلسه‌ی ۲ — محیط پروژه، رنگ‌ها، و git

**کلاس ویندوزی · دوره‌ی ۱۲ جلسه‌ای** (نقشه‌ی کامل: [course-plan-12-sessions.md](../course-plan-12-sessions.md))

> ✅ **این جلسه برگزار شد.** venv، requirements و rich کامل انجام شدند؛ **git نشد** —
> کلاس کندتر از برنامه پیش رفت چون گلوگاه واقعی تسلط بر ابزار بود.
> **بلوک git به [کیت جلسه‌ی ۳](../session-03/) منتقل شد**، همراه با یک درس ابزار
> (VS Code و ترمینال) که دقیقاً همان گلوگاه را می‌بندد.
> بخش «۵۷ تا ۸۵ — git» در راهنمای زیر را نادیده بگیرید.

دو موضوع در یک جلسه: **venv و requirements** · **rich**.
هر دو یک چیز مشترک دارند: عادت‌هایی که تفاوت «کد نوشتن» و «پروژه داشتن» را می‌سازند.

## از کجا شروع کنم؟

1. **[چک‌لیست آماده‌سازی](prep-checklist.md)** — با این شروع کنید. دو کار حیاتی دارد:
   **پلن آفلاین `pip install rich`** و **ست‌کردن هویت git روی همه‌ی لپ‌تاپ‌ها**.
   (بدون دومی، اولین commit هر دانش‌آموز خطا می‌دهد و ۱۰ دقیقه از بلوک git می‌رود.)
2. **[راهنمای مربی](instructor-guide.md)** — اسکریپت دقیقه‌به‌دقیقه + نردبان حذف +
   جدول مشکلات ویندوزی (جدا برای venv و git) + پلن B.
3. برگه‌ها را چاپ کنید (پایین).

## ⚠️ سه تصمیم مهم

**۱. این جلسه متراکم است.** ۹۰ دقیقه برای سه موضوع. راهنما یک **نردبان حذف** دارد:
دقیقاً چه چیزی را به چه ترتیبی حذف کنید، و سه چیزی که هرگز حذف نمی‌شوند.

**۲. git آخر می‌آید، نه اول.** تا وقتی بچه‌ها چیزی نساخته‌اند که ارزش از دست دادن
داشته باشد، «راه برگشت» انتزاعی است. اول بازی‌شان رنگی و خوشگل می‌شود، بعد
با «فاجعه‌ی طراحی‌شده» ازشان گرفته می‌شود. و پوشه‌ی `venv` که دقیقه‌ی ۲۴ ساخته شد،
دقیقه‌ی ۷۲ سؤال `.gitignore` را می‌سازد — همین پل، دو نیمه‌ی جلسه را یکی می‌کند.

**۳. ترمینال کلاس Command Prompt است، نه PowerShell.** یک تنظیم یک‌دقیقه‌ای در VS Code
که دو تله‌ی ویندوز را یک‌جا می‌بندد: خطای ExecutionPolicy در `activate`، و ساخته‌شدن
`requirements.txt` با انکودینگ UTF-16 که `pip` نمی‌تواند بخواند.

## معیار موفقیت جلسه

> پروژه‌ی هر تیم توسط تیم دیگر فقط با `requirements.txt` اجرا شده، بازی رنگی است،
> و هر دانش‌آموز مستقل می‌تواند: تغییر بدهد، `status` بگیرد، `add` و `commit` کند،
> و یک فایل خراب را با `restore` برگرداند.

## دو قانونی که به پوستر اضافه می‌شود

> **قانون ۲:** هر پروژه جعبه‌ابزار خودش را دارد.
> **قانون ۳:** کاری که commit نشده، انجام نشده.

## چیزهایی که امروز **نباید** اتفاق بیفتد

- ❌ `git branch`، `git remote`، GitHub — مال جلسه‌ی ۷
- ❌ `git reset --hard` — خطرناک‌ترین ابزار git را دست تازه‌کار ندهید
- ❌ پنل Source Control در VS Code — امروز با ترمینال، تا بفهمند زیر دکمه‌ها چه می‌گذرد
- ❌ `Panel` و `Table` از rich — عمق rich مال جلسه‌ی ۱۱
- ❌ ساختن کلاس یا شکستن فایل — مال جلسات ۳ و ۵
