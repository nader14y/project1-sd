Python Testing • pytest

pytest از صفر تا حرفه‌ای

این ارائه برای کسی طراحی شده که از تست‌نویسی هیچ پیش‌زمینه‌ای ندارد. از مفهوم Test و assert شروع می‌کنیم و قدم‌به‌قدم به Fixture، Parametrize، Exception Testing، Mock، Monkeypatch، Coverage و ساختار پروژه واقعی می‌رسیم.

روش استفاده: با دکمه‌های پایین یا کلیدهای ← و → بین اسلایدها حرکت کن.
02
مفهوم پایه

اصلاً Testing چیست؟

فرض کن این تابع را نوشته‌ای:

def add(a, b):
    return a + b

اگر فقط با print() خروجی را نگاه کنی، در پروژه‌های بزرگ خیلی زود کنترل از دستت خارج می‌شود.

assert add(2, 3) == 5
assert یعنی: من انتظار دارم این شرط درست باشد؛ اگر نیست، تست Fail شود.

05
ساختار ذهنی

Arrange / Act / Assert

def test_discount():
    # Arrange
    price = 100
    discount = 20

    # Act
    result = price - discount

    # Assert
    assert result == 80

Arrange

داده‌ها و dependencyها را آماده کن.

Act

رفتاری که می‌خواهی تست کنی اجرا کن.

Assert

خروجی واقعی را با انتظار مقایسه کن.

اصل مهم

هر Test بهتر است فقط یک رفتار مشخص را بررسی کند.

        ValueError,
        match="Cannot divide by zero"

        divide(10, 0)

08
Core Concept

Fixture چیست؟

import pytest

@pytest.fixture
def user():
    return {
        "name": "Ali",
        "age": 30,
        "active": True,
    }
def test_user_name(user):
    assert user["name"] == "Ali"
pytest نام پارامتر user را می‌بیند، Fixture هم‌نام را پیدا می‌کند و مقدارش را Inject می‌کند.

11
Data-Driven Tests

Parametrize

@pytest.mark.parametrize(
    "a,b,expected",
    [
        (1, 2, 3),
        (2, 3, 5),
        (10, 20, 30),
        (-1, 1, 0),
    ]
)
def test_add(a, b, expected):
    assert add(a, b) == expected

یک Test را با چند Dataset اجرا می‌کند؛ برای Edge Caseها فوق‌العاده مفید است.

Mocking

Mock و MagicMock

from unittest.mock import MagicMock

def test_checkout_success():
    gateway = MagicMock()
    gateway.charge.return_value = True

    service = OrderService(gateway)

    result = service.checkout(200)

    assert result == "success"
    gateway.charge.assert_called_once_with(200)
در Unit Test معمولاً API، Email، SMS، Payment Gateway، S3 و سرویس‌های بیرونی را Mock می‌کنیم.
16
Testing Strategy

Unit / Integration / E2E

Unit

یک بخش کوچک و مستقل؛ سریع و کم‌هزینه.

Integration

ارتباط چند Component؛ مثلاً API + Repository + DB.

E2E

کل مسیر از ورودی کاربر تا نتیجه نهایی.

قاعده

Unit زیاد، Integration کمتر، E2E کمتر از همه.

17
Best Practices

اصول تست حرفه‌ای

  • هر Test مستقل از Testهای دیگر باشد.
  • فقط Happy Path را تست نکن؛ Edge Case را هم ببین.
  • اسم Test باید رفتار مورد انتظار را توضیح دهد.
  • Behavior را تست کن، نه جزئیات Implementation.
  • Test باید Deterministic باشد.
  • Unit Test باید سریع بماند.

    ...
