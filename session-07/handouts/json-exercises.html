چرا این دو تمرین؟ در جلسه‌ی ۶ فقط یاد گرفتیم JSON را بخوانیم. این دو تمرین، آن طرف ماجرا را کامل می‌کنند: نوشتن در فایل، و گشتن در داده. هر دو، فایل مستقل‌اند و هیچ‌کدام بازی را دست نمی‌زنند.

➕ تمرین ۱ — ابزارِ اضافه‌کردن سؤال

هدف: چرخه‌ی «بخوان ← عوض کن ← بنویس» — همان کاری که هر برنامه‌ای با فایل‌هایش می‌کند.
و یک وعده: جلسه‌ی ۱ پرسیدم «خواهر کوچکت چطور سؤال اضافه کند؟» — با این ابزار، دیگر لازم نیست حتی فایل JSON را باز کند.

فایل تازه‌ای بساز به اسم add_question.py که وقتی اجرا می‌شود، سؤال‌ها را می‌پرسد و به questions.json اضافه می‌کند:

> python add_question.py

مرحله‌به‌مرحله

  1. فایل را بخوان و در یک متغیر بریز: questions = json.load(f) — با encoding="utf-8"
  2. با input() پنج چیز بپرس: متن، چهار گزینه (یکی‌یکی)، جواب درست، قدرت ویژه، دسته.
    برای چهار گزینه، حلقه بزن: for letter in "ABCD":
  3. یک دیکشنری با همان کلیدهای قالب رسمی بساز و questions.append(...) کن
  4. همه‌ی لیست را دوباره بنویس: json.dump(questions, f, ensure_ascii=False, indent=2)
⚠️ سه تله‌ی این تمرین
  • اگر قدرت ویژه خالی بود، باید None ذخیره شود (که در فایل می‌شود null) — نه رشته‌ی خالی ""
  • جواب درست را .strip().upper() کن؛ کسی که a تایپ می‌کند منظورش A است
  • فایل را با "w" باز می‌کنی؛ کلِ لیست را می‌نویسی، نه فقط سؤال تازه را. "w" اول همه‌چیز را پاک می‌کند
✅ از کجا بفهمم درست شد
  • ابزار را زدم، یک سؤال اضافه کردم، و بازی آن سؤال را نشان داد
  • questions.json را باز کردم: فارسی‌ها فارسی‌اند و فایل خوانا (تورفته) است
  • ابزار را سه بار زدم و هر سه سؤال سرِ جایشان هستند (سؤال قبلی پاک نشده)
⭐ اختیاری
اگر جوابِ درست چیزی جز A تا D بود، دوباره بپرس تا درست وارد کند (while). و در آخر، همان سؤال را به خودش نشان بده تا تأیید کند.

✅ از کجا بفهمم درست شد
  • روی بانکِ سالم اجرا کردم → گفت «هیچ مشکلی پیدا نشد»
  • عمداً یک گزینه از یک سؤال حذف کردم → همان شماره را گزارش داد
  • عمداً "correct": "E" گذاشتم → گرفتش
  • یک سؤال را عیناً کپی کردم → تکراری بودنش را گفت

⭐ اختیاری — برای کسی که حوصله دارد
در آخر گزارش بنویس کدام دسته کمترین سؤال را دارد و پیشنهاد بده چند سؤال اضافه شود تا همه‌ی دسته‌ها برابر شوند.
🤔 و یک سؤال که جوابش را روی همین برگه بنویس
هر دو ابزار امروز print و input دارند — ولی قانون ۴ می‌گوید موتور بازی حق ندارد. چرا این‌ها اشکالی ندارد؟

🏚 تمرین جانبی ۱ — خانه‌ی ارواح

صفحه‌ی ۳ · ربطی به Quiz Battle ندارد
هدف: تا حالا JSONت یک لیستِ صاف بوده. اینجا هر اتاق، کلیدِ اتاق‌های دیگر را در خودش دارد — یعنی داده‌ای که به داده‌ی دیگر ارجاع می‌دهد. این دیگر لیست نیست، نقشه است.

یک ماجراجویی متنی بنویس که نقشه‌ی house.json را بازی کند:

{
  "start": "hall",
  "rooms": {
    "hall": {
      "name": "راهروی ورودی",
      "text": "یک راهروی تاریک. یک شمع روی میز سوسو می‌زند.",
      "exits": { "شمال": "kitchen", "بالا": "landing" }
    },
    "kitchen": {
      "name": "آشپزخانه",
      "text": "قابلمه‌ای روی اجاق هنوز گرم است. یعنی کسی همین الان اینجا بوده؟",
      "item": "کلید زنگ‌زده",
      "exits": { "جنوب": "hall", "شرق": "cellar" }
    },
    "attic": { "needs": "کلید زنگ‌زده", "end": true, "exits": {} }
  }
}

برنامه باید چه کند

  1. از اتاقِ start شروع کند
  2. name و text اتاق را نشان دهد
  3. اگر اتاق item داشت، در کوله بگذارد (room.get("item") — اگر نداشت None)
  4. راه‌ها را نشان دهد و بپرسد «کجا بروم؟»
  5. اگر اتاقِ مقصد needs داشت و آن شیء در کوله نبود → قفل است
  6. اگر اتاق end داشت → بازی تمام
⭐ نکته‌ی اصلی این تمرین
وقتی تمام شد، فایل پایتونت را نگاه کن: اسم هیچ اتاقی در آن نیست. کل خانه، داستان، درها و اشیا در JSON زندگی می‌کنند.

یعنی همین یک برنامه، نقشه‌ی هر کسی را بازی می‌کند — مدرسه‌تان، خانه‌تان، هر چه بسازی. نقشه‌ات را به بغل‌دستی بده و مال او را بگیر و بازی کن.
✅ از کجا بفهمم درست شد
  • نقشه را تا اتاق پایانی رفتم و بازی تمام شد
  • بدون کلید سراغ درِ قفل رفتم → نگذاشت. با کلید → گذاشت
  • یک راهِ بی‌معنی تایپ کردم → برنامه نمُرد، فقط گفت «از این طرف راهی نیست»
  • یک اتاق تازه به JSON اضافه کردم و بدون دست‌زدن به کد رفتم داخلش
⭐⭐ بخش پیشرفته — بازرسِ نقشه (این را حتماً امتحان کن)
قبل از اینکه نقشه‌ات را به دوستت بدهی، یک check_house.py بنویس که چک کند:
  • هر دری به اتاقی می‌رود که واقعاً وجود دارد؟
  • اتاقی هست که ساخته‌ای ولی هیچ راهی به آن نیست؟
  • اصلاً اتاقی با end داری، یا بازی هیچ‌وقت تمام نمی‌شود؟
❌ 2 مشکل:
  • اتاق «hall»: درِ «غرب» به اتاقِ ناموجودِ «garden» می‌رود
  • اتاق «ghost» ساخته شده ولی هیچ راهی به آن نیست
راهنمایی برای مورد دوم: از start شروع کن، هر اتاقی که می‌بینی در یک لیست بریز، و از داخل همان لیست جلو برو.

💬 تمرین جانبی ۲ — کارآگاهِ گروه

صفحه‌ی ۴ · ربطی به Quiz Battle ندارد
هدف: گروه‌بندی — یعنی یک مشت داده‌ی به‌هم‌ریخته را از دو زاویه‌ی مختلف دسته کنی: هر نفر، و هر ساعت.

یک روزِ کاملِ چتِ یک گروه در chat.json است — ۳۶ پیام:

[
  { "from": "سارا", "time": "19:20", "text": "بچه‌ها یادتون نره فردا امتحان علوم داریم" },
  { "from": "پویا", "time": "19:22", "text": "چیییی؟ 😱" }
]

یک chat_detective.py بنویس که گزارشش را دربیاورد:

💬 36 پیام از 4 نفر

پرحرف‌ترین‌ها:
  1) سارا   ███████████ 11 پیام (31٪) · میانگین 18 حرف
  2) پویا   ██████████ 10 پیام (28٪) · میانگین 14 حرف

شلوغ‌ترین ساعت: 20:00 تا 20:59 با 13 پیام
سؤال‌ها: 6 تا از 36 پیام (17٪)

🤫 کم‌حرف‌ترین: امیر با فقط 7 پیام

باید حساب کنی

  1. هر نفر چند پیام داده — و چند درصدِ کل گروه است
  2. شلوغ‌ترین ساعت کدام بوده
  3. چند تا از پیام‌ها سؤال بوده‌اند (به «؟» ختم می‌شوند)
  4. بلندترین پیام مال چه کسی بود و چه ساعتی
  5. میانگین طول پیامِ هر نفر
🔑 تله‌ی اصلیِ این تمرین
ساعت، یک فیلد جدا نیست! فقط "time": "20:07" داری. باید خودت بیرونش بکشی: 
hour = message["time"].split(":")[0]     # "20:07" → "20"
و این درسِ بزرگ‌ترش این است: داده همیشه به شکلی که می‌خواهی نیست — باید بسازیش.
💡 دو راهنمایی
  • برای شمردن، یک دیکشنریِ شمارنده بساز: count[key] = count.get(key, 0) + 1 — یک‌بار برای نفرها، یک‌بار برای ساعت‌ها
  • برای مرتب‌کردن از زیاد به کم: sorted(count.items(), key=lambda item: item[1], reverse=True)
  • نوار "█" * count — همان ترفند تمرین جلسه‌ی ۴، حالا روی داده‌ی واقعی
✅ از کجا بفهمم درست شد

  • جمعِ پیام‌های همه‌ی نفرها دقیقاً ۳۶ می‌شود
  • یک پیام را دستی از فایل حذف کردم و همه‌ی عددها تغییر کردند
