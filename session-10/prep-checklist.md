## 🔴 چهار کار حیاتی قبل از کلاس

### ۰. دسترسیِ هر دو عضو تیم به repo را **امروز** چک کنید

کلِ جلسه روی این سوار است. اگر عضو دومِ تیمی نتواند push کند، آن تیم امروز
هیچ‌کاری نمی‌تواند بکند.

- [ ] برای هر تیم، **هر دو نفر** یک‌بار `git push` تستی روی یک branch آزمایشی بزنند
- [ ] `git config pull.rebase false` را روی همه‌ی لپ‌تاپ‌ها ست کنید
      (وگرنه موقع `pull` پیام divergent می‌گیرند و وقت می‌رود)
- [ ] در تنظیمات repo، گزینه‌ی **Allow merge commits** روشن باشد

### ۱. سناریوی branch و conflict را **یک‌بار کامل خودتان بروید**

این مهم‌ترین آماده‌سازی امروز است. روی یک کپی از پروژه:

- [ ] `git switch -c fix/duplicate-names` → بلوک لاگ + `ask_names` → commit → push
- [ ] برگردید به `main`، بعد `git switch -c fix/question-bank` **از روی main قدیمی**
      → همان بلوک لاگ (با نوشتنِ کمی متفاوت) + فیکس `QuestionBank` → commit → push
- [ ] PR اول را merge کنید → **باید تمیز merge شود**
- [ ] PR دوم را باز کنید → **باید conflict بدهد** ✅
- [ ] conflict را در VS Code حل کنید و ببینید نشانه‌ها چه شکلی‌اند
- [ ] `git log --oneline --graph` بزنید و شکلِ دوشاخه را ببینید
- [ ] یک commit بد بزنید و `git revert` کنید

> 💡 اگر conflict **اتفاق نیفتاد**، یعنی branch دوم را از روی main‌ِ *بعد از merge*
> ساخته‌اید. هر دو branch باید از **یک نقطه‌ی مشترک** شروع شوند.

### ۲. سه قتل را خودتان تمرین کنید

کلِ بلوکِ ۱۰ تا ۲۲ روی این است و باید **روان** اجرا شود، نه با دست‌پاچگی:

- [ ] یک پوشه‌ی سالم از پروژه‌ی کلاس داشته باشید و از `questions.json` یک **کپی پشتیبان** بگیرید
- [ ] 💀 **قتل ۱:** بازی را بزنید و هر دو نام را `علی` بگذارید → `ValueError` را ببینید
- [ ] 💀 **قتل ۲:** اسم `questions.json` را عوض کنید → `FileNotFoundError`
- [ ] 💀 **قتل ۳:** یک `,` اضافه آخر لیست بگذارید → `JSONDecodeError`
- [ ] بعد از هر سه، فایل را **برگردانید** و مطمئن شوید بازی سالم است

> 💡 اگر پروژکتور کوچک است، فونت ترمینال را بزرگ کنید — کلاس باید **اولین کلمه‌ی
> هر خطا** را بخواند، چون آن کلمه نوعِ خطاست و کلِ کلیدِ `except` همان است.

### 🔌 برنامه‌ی B — اگر اینترنت خراب شد

همه‌ی مراحل جز صفحه‌ی PR، لوکال هم کار می‌کنند:

```bat
git switch main
git merge fix/duplicate-names
```

«کد ریویو» را حضوری انجام دهید: هر نفر `git diff main..fix/...` را روی لپ‌تاپ
هم‌تیمی‌اش می‌خواند و **یک کامنت شفاهی** می‌دهد. conflict دقیقاً همان‌طور اتفاق می‌افتد.

- ❌ اجازه‌دادن به کسی که PR **خودش** را merge کند
- ❌ **گفتن کلمه‌ی `try` قبل از دقیقه‌ی ۱۸.** اول سه قتل
- ❌ قبول‌کردنِ `if player1_name == player2_name` در `game.py` — روی تخته بنویسید و خرابش کنید
- ❌ `except:` خالی، حتی برای «فعلاً»
