🔥 هشدار: جلسه‌ی بعد «آزمون آتش» داریم
جلسه‌ی بعد، تیم مقابل فقط و فقط از روی README.md شما، بازی‌تان را روی لپ‌تاپ خودش اجرا می‌کند. اجازه ندارید حرف بزنید یا کمک کنید. هر جا گیر کرد، یعنی README شما آنجا کم دارد. بخش الف را جدی بگیرید.

بخش الف — 📄 README.md

  1. یک فایل README.md در ریشه‌ی پروژه بساز که این شش بخش را داشته باشد: 
    ١. بازی چیست؟           (دو خط، برای کسی که هیچ نمی‌داند)
٢. چه چیزی لازم است؟     (پایتون ۳.۱۰+، ویندوز)
٣. نصب                  (دستورهای دقیق venv و requirements)
٤. اجرا                 (دقیقاً چه بزنم؟)
٥. قواعد بازی            (امتیاز، بونوس سرعت، قدرت ویژه)
٦. سؤال اضافه کردن       (questions.json و قالبش)
    هر دستور را در بلوک کد بگذار، و دقیقاً همان چیزی را بنویس که باید تایپ شود. «محیط مجازی را فعال کن» کافی نیست — بنویس venv\Scripts\activate.
  2. خودت امتحانش کن: پروژه را در یک پوشه‌ی کاملاً تازه کپی کن و فقط از روی README پیش برو. هر جا گیر کردی، README را درست کن.
    این تنها راه فهمیدنِ چیزی است که جا انداخته‌ای.

بخش ب — ⏪ دو دستورِ سفر در زمان

  1. یک تغییرِ عمداً بد بزن (مثلاً یک console.print مزاحم اضافه کن)، commit کن، و بعد با revert برش گردان. 
    git log --oneline          ← هشِ commitِ بد را پیدا کن
git revert a1b2c3d
    بعدش git log --oneline بزن. چند commit می‌بینی؟ ______ و چرا git آن commit را پاک نکرد؟
  2. این یکی را سر کلاس نزدیم — یک فایل را به نسخه‌ی یک commitِ قدیمی برگردان: 
    git restore --source=<هش> -- questions.json
    اول questions.json را خراب کن، بعد با این دستور برش گردان. فرقش با git restore questions.json چیست؟

بخش ج — 🥅 تورِ آخر

  1. اگر سر کلاس نرسیدیم، KeyboardInterrupt و تورِ آخر را اضافه کن (شکلش روی کارت خطاست)، و هر دو را امتحان کن:
    وسط بازی Ctrl+C بزن → باید «خداحافظ» بگوید، نه صفحه‌ی قرمز.

بخش د — 🛡 دو نگهبان دیگر (قانون ۹)

  1. دو تستِ نگهبانِ دیگر به tests/test_guards.py اضافه کن:
    ۱) بانک سؤالِ خالی ([]) باید ValueError بدهد
    ۲) بانکی که از ROUNDS کمتر سؤال دارد، موقع pick(5) باید خطا بدهد
  2. ثابت کن نگهبانت واقعاً نگهبانی می‌دهد: آن try یا ifی که امروز اضافه کردیم را موقتاً پاک کن، pytest بزن، و متن قرمز را اینجا بنویس:
    بعد برگردانش و مطمئن شو دوباره سبز است.

بخش ه — 🤔 دو سؤال (روی همین برگه)

  1. یک خرابیِ دیگر نام ببر که بازی ما هنوز برایش آماده نیست. بدون آن داده می‌شود بازی کرد؟ پس باید فریاد بزند یا ادامه بدهد؟
  2. فرض کن بازی‌ات روی لپ‌تاپ ۱۰۰ نفر است و یکی‌شان می‌گوید «خراب شد». game.log روی لپ‌تاپ اوست، نه تو. چه کار می‌کنی؟
    جلسه‌ی بعد جوابِ حرفه‌ای‌اش را می‌بینی.
قبل از تحویل، چک کن
  • نام تکراری زدم → دوباره پرسید، نمُرد
  • questions.json را قایم کردم → پیام فارسیِ روشن، بدون صفحه‌ی قرمز
  • یک ویرگول اضافه گذاشتم → پیام شماره‌ی خط را گفت
  • leaderboard.json را خراب کردم → بازی ادامه داد
  • Ctrl+C زدم → «خداحافظ»
  • game.log ساخته می‌شود، فارسی‌اش سالم است، و در .gitignore است
  • pytest سبز است (قانون ۷) و push کرده‌ام
  • کارم را روی یک branch زدم و با PR وارد main کردم (قانون ۸)
  • main سالم است: git switch main && git pull && pytest سبز
  • پروژه را در پوشه‌ی تازه فقط از روی README اجرا کردم و کار کرد
