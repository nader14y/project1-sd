⏳ سفر در زمان با git

Quiz Battle · جلسه‌ی ۵ · صفحه‌ی ۱ از ۲
هفته‌ی پیش یاد گرفتیم save کنیم و به آخرین save برگردیم. امروز یاد می‌گیریم در تاریخچه قدم بزنیم.

۱ چه چیزی عوض شده؟

git status        ← کدام فایل عوض شده
git diff          ← چه چیزی عوض شده، خط‌به‌خط
خط با - = آنچه بود  ·  خط با + = آنچه شد.
👉 عادت طلایی: قبل از هر commit یک git diff بزن. نصف اشتباه‌ها همان‌جا معلوم می‌شود — print دیباگی جامانده، خطی که اشتباهی پاک شده.

۲ تاریخچه را بگرد

git log --oneline           ← لیست کوتاه همه‌ی commitها
git log --oneline --stat    ← هر commit چه فایل‌هایی را دست زد
git show 3f2a1b9            ← آن روز دقیقاً چه کار کردم؟
⚠️ ترمینال هنگ نکرده! خروجی diff، log و show در یک صفحه‌ی مخصوص باز می‌شود. با فلش حرکت کن و با کلید q ببندش.

۳ ⭐ برگشتن به یک save قدیمی

git restore game.py
        ← برگرد به آخرین save

git restore --source=3f2a1b9 -- game.py
        ← برگرد به آن save
hash را از git log --oneline کپی کن — ۷ کاراکتر اول کافی است.
⚠️ حرف -- را جا نینداز، وگرنه git گیج می‌شود.
این دستور تاریخچه را پاک نمی‌کند.
فقط فایل روی دیسک را عوض می‌کند — هر لحظه می‌توانی برگردی.

۴ باطل کردن یک commit

git revert 3f2a1b9
یک commit جدید می‌سازد که کارِ آن commit را برمی‌گرداند. مثل نوشتن «صفحه‌ی قبل را باطل کردم» در دفتر — نه پاره‌کردن صفحه.

سه ابزار، سه کار متفاوت

دستورچه می‌کندتاریخچه
git restore <file>فایل → آخرین commitدست‌نخورده
git restore --source=<hash> -- <file>فایل → آن commitدست‌نخورده
git revert <hash>commit جدیدی که آن را باطل می‌کندیکی اضافه می‌شود
git تقریباً هیچ‌وقت چیزی را گم نمی‌کند — به شرطی که commit کرده باشی.

☁️ پروژه روی GitHub

Quiz Battle · جلسه‌ی ۵ · صفحه‌ی ۲ از ۲
git یک برنامه است روی لپ‌تاپ تو — تا امروز یک بایت هم به اینترنت نرفت.
GitHub یک سایت است: خانه‌ای در اینترنت برای repo تو.

عضو اول ساخت repo و اولین push

github.com → دکمه‌ی + بالا راست → New repository → اسم: quiz-battle → Private
🚨 مهم‌ترین تله: تیک Add a README و Add .gitignore را نزن. repo باید کاملاً خالی باشد، وگرنه اولین push رد می‌شود. 
git remote add origin https://github.com/USERNAME/quiz-battle.git
git branch -M main
git push -u origin main
remote add originبه git می‌گویی خانه‌ی اینترنتی‌ات کجاست. origin فقط یک اسم مستعار برای آن آدرس است.
branch -M mainمطمئن می‌شوی اسم شاخه‌ی اصلی main است.
push -u origin mainهلش بده بالا. -u یعنی از این به بعد فقط git push کافی است.
🔐 یک پنجره باز می‌شود و می‌گوید با مرورگر وارد GitHub شو → Authorize. یک‌بار برای همیشه.
⚠️ اگر رمز عبور خواست، رمز را نزن — GitHub رمز را قبول نمی‌کند.

عضو اول دعوت هم‌تیمی

repo → Settings → Collaborators → Add people → نام کاربری هم‌تیمی.
هم‌تیمی در مرورگر خودش، از زنگ اعلان‌ها یا ایمیل، دعوت را قبول می‌کند.

عضو دوم clone کردن پروژه

cd C:\dev
git clone https://github.com/USERNAME/quiz-battle.git
cd quiz-battle
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python game.py
⚠️ حتماً اول cd C:\dev — وگرنه پروژه داخل پروژه clone می‌شود.
🤔 چرا پوشه‌ی venv در آنچه clone شد نبود؟ چون در .gitignore است — و از روی requirements.txt دوباره ساخته می‌شود.

چرخه‌ی روزانه — تا آخر دوره ده‌ها بار

git pull
←
کار کن
←
git commit
←
git push
pull = اول ببین هم‌تیمی‌ات چه فرستاده  ·  push = آخر، کارت را بفرست
