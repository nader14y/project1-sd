بخش الف — ⏳ سفر در زمان

  1. یک تغییر کوچک در بازی بده، ذخیره کن ولی commit نکن، و git diff بزن.
    یک خط از خروجی که با - شروع می‌شود را اینجا بنویس:
  2. با git log --oneline یک commit قدیمی پیدا کن و فایل را به آن برگردان: 
    git restore --source=<hash> -- game.py
    بازی را اجرا کن و ببین چه چیزی عوض شد. بعد با git restore game.py برگرد.
    آن نسخه چه چیزی نداشت که الان دارد؟
  3. یکی از commitهای خودت را با git show <hash> ببین.
    یادت باشد: با q بسته می‌شود.

بخش ب — ☁️ کار تیمی روی GitHub

  1. حداقل ۳ سؤال جدید به بازی اضافه کن، در ۳ commit جدا، و همه را push کن. 
    git add .
git commit -m "Add three history questions"
git push
  2. هم‌تیمی‌ات کار کرده — بیاورش: 
    git pull
    سؤال‌های او را در فایل خودت ببین. چند سؤال اضافه کرده بود؟
  3. در مرورگر، صفحه‌ی repo تیمت را باز کن و روی تب Commits برو.
    روی یکی از commitهای هم‌تیمی‌ات کلیک کن و تغییرش را ببین. (این همان git show است، فقط با ماوس.)
قبل از تحویل، چک کن
  • در صفحه‌ی GitHub، commitهای هر دو عضو تیم دیده می‌شود
  • git status تمیز است و git push چیزی برای فرستادن ندارد
  • بازی بدون خطا اجرا می‌شود
  • یک‌بار git restore --source را تجربه کردم
  • هر دو سؤال این برگه را جواب داده‌ام
⭐ اختیاری — برای کسی که حوصله دارد
یک فایل README.md در پروژه بساز و در آن بنویس بازی‌ات چیست و چطور اجرا می‌شود. push کن و صفحه‌ی repo را refresh کن — GitHub خودش نمایشش می‌دهد.
(جلسه‌ی ۹ حرفه‌ای‌اش می‌کنیم، ولی همین حالا هم می‌توانی شروع کنی.)
