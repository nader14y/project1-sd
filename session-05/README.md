# کیت جلسه‌ی ۵ — سفر در زمان با git، و پروژه روی GitHub

**کلاس ویندوزی · دوره‌ی ۱۲ جلسه‌ای**

دو بلوک: **بقیه‌ی git محلی** (دیدن تغییرها و برگشتن به هر commitی، نه فقط آخری) و
**GitHub** (repo، push، و `clone` توسط عضو دوم تیم).

## از کجا شروع کنم؟

1. **[چک‌لیست آماده‌سازی](prep-checklist.md)** — سه کار حیاتی. مهم‌ترینش:
   **احراز هویت GitHub**. بزرگ‌ترین ریسک امروز آموزش نیست، `push`ی است که گیر می‌کند.
2. **[راهنمای مربی](instructor-guide.md)** — دقیقه‌به‌دقیقه + نردبان حذف + پلن B آفلاین
   + جدول کامل خطاهای GitHub.
3. برگه‌ها را چاپ کنید (پایین).

## ⚠️ پنج تصمیم مهم

**۱. ستاره‌ی بلوک اول `git restore --source=<hash>` است.** هفته‌ی پیش به آخرین commit
برگشتند؛ امروز به **هر** commitی. فعالیتش هم عملی است: عمداً به نسخه‌ی قبل از رنگی‌شدن
برمی‌گردند، می‌بینند رنگ‌ها رفته، بعد برمی‌گردند.

**۲. دعوت collaborator را دقیقه‌ی ۴۵ بفرستید، نه ۶۵.** قبول‌کردن دعوت چند دقیقه طول
می‌کشد؛ اگر آن را به لحظه‌ی نیاز بسپارید، ۱۰ دقیقه معطل می‌مانید.

**۳. repo باید کاملاً خالی ساخته شود** — بدون README، بدون .gitignore، بدون license.
این مهم‌ترین تله‌ی امروز است: اگر README داشته باشد، اولین `push` با پیام گیج‌کننده‌ی
`non-fast-forward` رد می‌شود.

**۴. conflict و PR امروز نه.** امروز به‌اندازه‌ی کافی تازگی دارد (پنج دستور git +
کل GitHub). جلسه‌ی ۸ سراغشان می‌رویم — و آن‌وقت پروژه `engine.py` و `game.py` دارد،
پس تقسیم کار بین دو عضو **طبیعی** است و conflict خودش پیش می‌آید، نه مصنوعی.

**۵. با ترمینال، نه GitHub Desktop و نه پنل Source Control.** مثل جلسه‌ی ۳:
دستورها تایپ می‌شوند تا بفهمند زیر دکمه‌ها چه می‌گذرد.

## معیار موفقیت جلسه

> repo هر تیم روی GitHub است، هر دو عضو حداقل یک‌بار `push` کرده‌اند، عضو دوم پروژه را
> `clone` کرده و اجرا کرده است، و هر دانش‌آموز می‌تواند یک فایل را به یک commit
> **قدیمی** برگرداند.

## قانونی که به پوستر اضافه می‌شود

> **قانون ۵: هر جلسه با `push` تمام می‌شود.**
> تا امروز خراب‌شدن لپ‌تاپ یعنی از دست دادن یک هفته. از امروز یعنی **صفر**.
