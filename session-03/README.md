# کیت جلسه‌ی ۳ — ابزارها: VS Code و git

**کلاس ویندوزی · دوره‌ی ۱۲ جلسه‌ای** (نقشه‌ی کامل: [course-plan-12-sessions.md](../course-plan-12-sessions.md))

جلسه‌ی ۲ کند پیش رفت و git نشد — چون گلوگاه، مفهوم نبود: **ابزار بود.**
این جلسه دقیقاً همان دو گلوگاه را می‌بندد (فایل/پوشه/ذخیره، و ترمینال) و بعد git را
با فرصت کامل درس می‌دهد.

## از کجا شروع کنم؟

1. **[چک‌لیست آماده‌سازی](prep-checklist.md)** — امروز اینترنت لازم نیست، ولی
   **هویت git باید از قبل روی همه‌ی لپ‌تاپ‌ها ست شده باشد**، وگرنه اولین commit خطا می‌دهد.
2. **[راهنمای مربی](instructor-guide.md)** — دقیقه‌به‌دقیقه + نردبان حذف + جدول مشکلات ویندوزی.
3. برگه‌ها را چاپ کنید (پایین).

## ⏱ چیدمان جلسه

| زمان | بخش |
|---|---|
| ۰ – ۶ | تمرین + «چرا هفته‌ی پیش کند بودیم؟» |
| ۶ – ۱۴ | درس ۱: پروژه، پوشه، و **نقطه‌ی سفید** |
| ۱۴ – ۲۲ | درس ۲: ترمینال کجاست و چه می‌گوید |
| ۲۲ – ۳۲ | 🏁 **مسابقه‌ی راه‌اندازی** (با کرنومتر) |
| ۳۲ – ۴۰ | 💣 فاجعه‌ی طراحی‌شده |
| ۴۰ – ۶۲ | git: اولین commit + `.gitignore` |
| ۶۲ – ۷۴ | 🎉 سفر در زمان (`git restore`) + دیدن تغییرها در VS Code |
| ۷۴ – ۹۰ | پیام commit، سه commit تمرینی، قانون ۳ |

git امروز **۵۰ دقیقه** دارد — به‌جای ۲۸ دقیقه‌ی فشرده‌ی طرح قبلی.

## ⚠️ چهار تصمیم مهم

**۱. هیچ سخنرانی‌ای درباره‌ی ادیتور.** هر مفهوم = یک درد که نشان می‌دهید، یک میان‌بُر که
حلش می‌کند، و تمرین فوری. سخنرانی درباره‌ی VS Code برای این سن مرگ است.

**۲. Auto Save را بعد از درس روشن کنید، نه قبلش.** اول باید درد «چرا تغییرم اعمال نشد»
را ببینند و نقطه‌ی سفید را بشناسند؛ بعد بگذارید کامپیوتر خودش انجامش دهد. اگر از اول
روشن باشد، هرگز نمی‌فهمند — و روی کامپیوتری که Auto Save ندارد گیر می‌کنند.

**۳. دستورهای git در ترمینال تایپ می‌شوند، پنل Source Control فقط برای *دیدن*.**
نوار رنگی کنار شماره‌ی خط و نمای دو ستونه بهترین ابزار برای فهم «چه چیزی عوض شد» است —
ولی دکمه‌های Stage و Commit امروز زده نمی‌شوند.

**۴. مسابقه‌ی راه‌اندازی از این جلسه به بعد، گرم‌کردن ثابت هر جلسه است.**
تسلط بر ابزار از تکرار می‌آید، نه از یک جلسه آموزش. زمان‌ها را یادداشت کنید —
پیشرفت ملموس، بهترین انگیزه است.

## معیار موفقیت جلسه

> هر دانش‌آموز مستقل می‌تواند پروژه را از صفر باز کند و اجرا کند (زیر یک دقیقه)،
> و مستقل می‌تواند: تغییر بدهد، `status` بگیرد، `add` و `commit` کند، و یک فایل خراب
> را با `restore` برگرداند.

## قانونی که به پوستر اضافه می‌شود

> **قانون ۳:** کاری که commit نشده، انجام نشده.

## چیزهایی که امروز **نباید** اتفاق بیفتد

- ❌ `git branch`، `git remote`، GitHub — مال جلسه‌ی ۷
- ❌ `git reset --hard` — خطرناک‌ترین ابزار git را دست تازه‌کار ندهید
- ❌ زدن دکمه‌های Stage/Commit در پنل Source Control — امروز فقط نگاه‌کردن
- ❌ میان‌بُرهای فانتزی (multi-cursor، snippet) — فقط چیزهایی که هفته‌ی پیش وقت‌تان را خوردند
- ❌ `Panel` و `Table` از rich — عمق rich مال جلسه‌ی ۱۱
