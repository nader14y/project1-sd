# ۰ تا ۶ — بررسی تمرین + طرح مسئله

## دقیقه‌ی ۰ تا ۳ — تمرین خانه

**دو تیم** منوی رنگی‌شان را نشان دهند. دنبال این باشید: منو رنگی است؟ با ۲ خارج می‌شود؟
ورودی اشتباه برنامه را نمی‌کشد؟

اگر کسی `if choice == 1` بدون کوتیشن نوشته بود، **همان‌جا ۳۰ ثانیه**: در ترمینال
`"1" == 1` را نشان بدهید. `input()` همیشه رشته می‌دهد.

## دقیقه‌ی ۳ تا ۶ — «چرا هفته‌ی پیش کند بودیم؟»

این را **از خودشان بپرسید**، خودتان جواب ندهید:

> «هفته‌ی پیش قرار بود سه چیز یاد بگیریم، دو تا شد. چرا؟ صادق باشید.»

جواب‌هایی که می‌شنوید: «فایلم گم شد»، «نفهمیدم ترمینال کجاست»، «تغییرم اعمال نمی‌شد»،
«ندونستم چی تایپ کنم».

بعد جمع‌بندی — و این جمله مهم است:

> «هیچ‌کدام از این‌ها ربطی به پایتون نداشت. همه‌شان ربط داشت به **ابزار**.
> یک نجار خوب اول اره‌اش را می‌شناسد. امروز اره‌مان را می‌شناسیم — و بعد
> کاری می‌کنیم که هیچ‌وقت کدمان گم نشود.»

# ۶ تا ۱۴ — درس ۱: پروژه، پوشه، و نقطه‌ی سفید

## 🔴 مفهوم ۱ (۳ دقیقه): پوشه را باز کن، نه فایل

**اول درد را نشان بدهید.** روی پرده، VS Code را ببندید و **فقط `game.py`** را باز کنید
(دابل‌کلیک روی فایل). حالا:

- نوار کنار (Explorer) خالی است — هیچ فایل دیگری دیده نمی‌شود
- `Ctrl+` ` بزنید → ترمینال در پوشه‌ای عجیب باز می‌شود (مثلاً `C:\Users\...`)
- `venv\Scripts\activate` → **خطا**
- `python game.py` → **خطا: فایل پیدا نشد**

بگویید: «این دقیقاً همان چیزی است که هفته‌ی پیش برای چند نفرتان اتفاق افتاد.»

**راه درست:**

> `File` → `Open Folder…` → `C:\dev\quiz-battle`

حالا نگاه کنید: نوار کنار درخت پروژه را نشان می‌دهد، و ترمینال **در همان پوشه** باز می‌شود.

**قانون کلاس، روی تخته:**
> ## همیشه پوشه را باز کن، نه فایل.

**تمرین فوری (۱ دقیقه):** همه VS Code را ببندند و پروژه را با `Open Folder` باز کنند.
چک: بالای نوار کنار باید بنویسد `QUIZ-BATTLE`.

## 🔴 مفهوم ۲ (۴ دقیقه): نقطه‌ی سفید — «چرا تغییرم اعمال نشد؟»

این تک‌نشانه، **بزرگ‌ترین منبع سرگردانی هفته‌ی پیش** بود.

روی پرده:
1. در `game.py` یک پیام را عوض کنید (مثلاً «درست!» → «آفرین!»)
2. **انگشتتان را بگذارید روی تب فایل:** یک **نقطه‌ی سفید ●** کنار اسم فایل آمده
3. بدون ذخیره‌کردن اجرا کنید → **پیام قدیمی می‌آید!**
4. بپرسید: «چرا؟»
5. `Ctrl+S` → نقطه به ✕ تبدیل می‌شود → اجرا کنید → پیام جدید 🎉

> «نقطه‌ی سفید یعنی: چیزی که روی صفحه می‌بینی، با چیزی که روی دیسک است، **یکی نیست.**
> پایتون فایل روی دیسک را اجرا می‌کند، نه چیزی که تو می‌بینی.»

**و حالا بگذارید کامپیوتر خودش انجامش دهد:**

> `File` → `Auto Save` ✔️

> «الان که فهمیدید **چرا**، بگذارید خودکار شود. ولی نشانه‌ی نقطه را یادتان بماند —
> روی کامپیوتری که Auto Save ندارد، همان نقطه نجاتتان می‌دهد.»

⚠️ حتماً به این ترتیب: **اول درد، بعد Auto Save.** اگر از اول روشنش کنید، هرگز نمی‌فهمند.

## 🔴 مفهوم ۳ (۳ دقیقه): فایل ساختن در جای درست

دقیقه‌ی ۵۴ باید یک فایل به اسم `.gitignore` بسازند. الان تمرینش کنید:

- در نوار کنار، **روی نام پوشه‌ی پروژه** کلیک کنید (نه روی یک فایل!)
- آیکون **New File** بالای نوار کنار
- اسم: `test.txt`

**تله‌ای که باید ببینند:** اگر قبلش روی یک **پوشه‌ی دیگر** کلیک کرده باشید، فایل آنجا
ساخته می‌شود. یک‌بار عمداً اشتباه بسازید و نشان بدهید.

> «فایل همیشه جایی ساخته می‌شود که در نوار کنار انتخاب شده. **قبل از New File،
> نگاه کن چه چیزی انتخاب است.**»

بعد `test.txt` را پاک کنند (راست‌کلیک → Delete).

**⏸ نقطه‌ی توقف ۱:** همه پوشه را باز کرده‌اند، Auto Save روشن است، و یک‌بار فایل ساخته و پاک کرده‌اند؟

# ۱۴ تا ۲۲ — درس ۲: ترمینال کجاست و چه می‌گوید

## دقیقه‌ی ۱۴ تا ۱۷ — سه چیزی که خط ترمینال به تو می‌گوید

روی پرده، ترمینال را باز کنید (`Ctrl+` `) و **خط prompt را با انگشت نشان بدهید**:

```
(venv) C:\dev\quiz-battle>
  ↑           ↑
  │           └── کجا هستی
  └── جعبه‌ابزار فعال است
```

> «این خط تنبل نیست، **گزارش وضعیت** است. قبل از هر دستور، یک نگاه به آن بینداز:
> اگر `(venv)` نبود، pip کار نمی‌کند. اگر مسیر عوضی بود، `python game.py` فایل را پیدا نمی‌کند.»

**قانون کلاس:**
> ## قبل از هر خطا، اول خط ترمینال را بخوان.

## دقیقه‌ی ۱۷ تا ۲۰ — چهار کلید که وقت‌تان را برمی‌گرداند

این چهار مورد بیشترین صرفه‌جویی را دارند. هر کدام را نشان بدهید و **همان لحظه تمرین کنند**:

| کلید | چه می‌کند | چرا مهم است |
|---|---|---|
| **↑ (فلش بالا)** | دستور قبلی را برمی‌گرداند | دیگر `venv\Scripts\activate` را تایپ نمی‌کنید — دو بار ↑ و Enter |
| **Tab** | اسم فایل/پوشه را کامل می‌کند | `python ga` + Tab → `python game.py` |
| **Ctrl+C** | برنامه‌ی در حال اجرا را متوقف می‌کند | وقتی بازی وسط سؤال گیر کرده |
| **cls** | صفحه‌ی ترمینال را پاک می‌کند | وقتی شلوغ شد |

**تمرین فوری (۲ دقیقه):** «بازی را اجرا کنید، وسطش Ctrl+C بزنید، بعد با **فلش بالا**
دوباره اجرایش کنید. سه بار.»

بچه‌ها معمولاً از فلش بالا ذوق می‌کنند — بگذارید ذوق کنند. این تک‌کلید، ده دقیقه از
جلسه‌ی بعد را نجات می‌دهد.

## دقیقه‌ی ۲۰ تا ۲۲ — خواندن پیام خطا + دو ابزار

فایل `live-code/broken_game.py` را باز کنید و اجرا کنید. خطا می‌دهد.

**خطا را از پایین به بالا بخوانید:**

```
  File "broken_game.py", line 26
    print("✅ درست!")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 25
```

| کجا | چه می‌گوید |
|---|---|
| **آخرین خط** | **نوع** خطا (`IndentationError`) |
| خط `File "...", line 26` | **کجا** — و در VS Code این خط **قابل کلیک** است |

**دو ابزار:**
- روی `broken_game.py:26` در ترمینال **کلیک کنید** → VS Code می‌رود سر همان خط
- یا `Ctrl+G` بزنید و شماره‌ی خط را وارد کنید

> «پیام خطا دشمن نیست؛ **آدرس** است. آخرین خط می‌گوید چه شد، خط بالاترش می‌گوید کجا.»

**⚠️ اگر دکمه‌ی ▶ استفاده می‌کنند:** یک‌بار `Ctrl+Shift+P` → `Python: Select Interpreter`
→ آن گزینه‌ای که `venv` در مسیرش دارد. وگرنه دکمه‌ی ▶ پایتون سیستم را اجرا می‌کند و
`rich` را پیدا نمی‌کند — همان خطای مرموز هفته‌ی پیش.

# ۲۲ تا ۳۲ — 🏁 مسابقه‌ی راه‌اندازی

**این فعالیت از این جلسه به بعد، گرم‌کردن ثابت هر جلسه است.**
برگه‌ی `handouts/speed-run.html` را پخش کنید.

هدف: **از VS Code بسته، تا بازی در حال اجرا.** شش قدم:

```
۱) VS Code را باز کن
۲) File → Open Folder → C:\dev\quiz-battle
۳) Ctrl+`  (ترمینال)
۴) venv\Scripts\activate        ← فلش بالا هم امتحان کن!
۵) python game.py               ← Tab را امتحان کن
۶) یک سؤال جواب بده، بعد Ctrl+C
```

| دور | چطور | زمان هدف |
|---|---|---|
| ۱ | با هم — شما قدم‌ها را بلند می‌گویید، همه هم‌زمان | مهم نیست |
| ۲ | خودشان، با کرنومتر خودشان، زمان را روی برگه بنویسند | زیر ۶۰ ثانیه |
| ۳ | **مسابقه‌ی تیمی** — سریع‌ترین تیم برنده | زیر ۳۰ ثانیه |

بین دورها بپرسید: «کی از فلش بالا استفاده کرد؟ چقدر سریع‌تر شد؟»

> «این تمرین را هر هفته اول کلاس تکرار می‌کنیم. هدف این است که یک روز بدون فکر کردن
> انجامش بدهید — مثل بند کفش.»

⏱ اگر عقب هستید، دور ۳ را حذف کنید ولی **دور ۲ را نگه دارید**.

## 📌 آیین «میان‌بُر هفته»

برگه‌ی میان‌بُرها **دو صفحه** است و حدود ۴۰ کلید دارد. **امروز فقط هشت‌تای ⭐ را کار کنید** —
بقیه مرجع است، نه درس.

از هفته‌ی بعد، هر جلسه در همان ۵ دقیقه‌ی گرم‌کردن **دو میان‌بُر تازه** را اعلام کنید،
روی گوشه‌ی تخته بنویسید، و تا آخر جلسه هر جا فرصت شد یادآوری کنید:
«الان می‌شد با کدام میان‌بُر این کار را کرد؟»

ترتیب پیشنهادی برای جلسات بعد:

| جلسه | دو میان‌بُر هفته | چرا همان هفته |
|---|---|---|
| ۴ | `Shift+Alt+↓` (کپی خط) · `Tab / Shift+Tab` روی چند خط | جلسه‌ی کلاس‌ها؛ بلوک‌ها مدام جابه‌جا می‌شوند |
| ۵ | `Ctrl+P` (باز کردن سریع فایل) · `Ctrl+Tab` | از این جلسه چند فایل داریم |
| ۶ | `Ctrl+F` · `F3` | گشتن در تست‌ها و کد |
| ۷ | `Ctrl+Shift+G` (پنل git) · `Ctrl+Shift+T` | جلسه‌ی GitHub و conflict |
| ۸ | `Ctrl+D` · `Ctrl+Shift+L` (چند مکان‌نما) | جلسه‌ی ریویو؛ اصلاح تکراری در چند جا |
| ۹ | `Ctrl+G` · `Ctrl+/` | جلسه‌ی دیباگ — پریدن سر خط خطا و کامنت‌کردن موقت |
| ۱۰ | `Win+Shift+S` (اسکرین‌شات) | برای Issue و README اسکرین‌شات لازم می‌شود |

`Ctrl+D` و `Ctrl+Shift+L` را بگذارید برای وقتی که کلاس کمی مسلط شده — این دو تا
«باحال»‌اند و بچه‌ها با دیدنشان ذوق می‌کنند، ولی زودتر از موقع فقط گیجشان می‌کند.

# ۳۲ تا ۴۰ — 💣 فاجعه‌ی طراحی‌شده

**این ۸ دقیقه، قلب بلوک git است. کوتاهش نکنید.**

با لحن کاملاً عادی، مثل یک تسک معمولی:

> «یک تغییر کوچک: سیستم امتیاز را بازنویسی کنید. به‌جای ۱۰، هر سؤال **۲۰ امتیاز** بدهد،
> و جواب غلط **۵ امتیاز کم** کند. چهار دقیقه وقت دارید.»

بگذارید واقعاً انجامش بدهند. اجرا کنند. کار می‌کند. حالا:

> «عالی. راستش... **مدیرِ محصول (یعنی من) نظرش عوض شد.** برگردید دقیقاً به نسخه‌ی قبل.
> دقیقاً. همان‌طور که بود.»

بگذارید `Ctrl+Z` بزنند. برای چند نفر کار می‌کند — **و برای چند نفر نه**:
- کسی که فایل را بسته و باز کرده → تاریخچه‌ی Ctrl+Z رفته
- کسی که چند جای مختلف را دست زده → یادش نیست کجاها
- کسی که زیادی Ctrl+Z زده → حالا رنگ‌های هفته‌ی پیشش هم رفته!

**همان‌ها را بلند بپرسید:** «الان دقیقاً همان نسخه‌ی قبل را داری؟ مطمئنی؟»

بعد جمله‌ی کلیدی:

> «برنامه‌نویس واقعی از خراب‌کردن نمی‌ترسد، چون **همیشه راه برگشت دارد.**
> امروز آن راه را می‌سازیم.»

# ۴۰ تا ۵۴ — git: اولین commit

## تشبیه (۲ دقیقه، روی تخته)

> «git دکمه‌ی **save** بازی است. commit یعنی save. هر جا save کردی، هر وقت خواستی برمی‌گردی.»

```
پوشه‌ی کار  ──add──▶  سبد خرید  ──commit──▶  آلبوم عکس
(working)            (staging)              (history)
```

> «هر چیزی که می‌سازی توی پوشه‌ی کار است. آنچه می‌خواهی این دفعه ثبت شود را می‌گذاری
> در سبد. بعد از سبد یک عکس می‌گیری و می‌چسبانی در آلبوم. **آلبوم هیچ‌وقت پاک نمی‌شود.**»

## دستورها (۱۲ دقیقه)

```bat
git init
git status
```

`git status` همه‌چیز را **قرمز** نشان می‌دهد = «ناشناخته، هنوز در سبد نیست».

**⛔ اینجا توقف کنید — قبل از `git add`**

بگذارید خوب به خروجی نگاه کنند. پوشه‌ی `venv` هم آنجاست، با کلی فایل.

> **«پوشه‌ی venv باید در آلبوم باشد؟ چرا نه؟»**

جواب را **هفته‌ی پیش** خودشان دادند: «چون سنگین است و از روی `requirements.txt` دوباره
ساخته می‌شود.» اگر یادشان نیامد، به آزمون تعویض هفته‌ی پیش ارجاع بدهید.

# ۵۴ تا ۶۲ — .gitignore

حالا از مهارت دقیقه‌ی ۱۱ استفاده می‌کنند: **فایل ساختن در جای درست.**

- روی **نام پوشه‌ی پروژه** در نوار کنار کلیک کنند
- New File → اسم دقیقاً: `.gitignore`

⚠️ **دو تله:**
- اسم با **نقطه شروع می‌شود** و **پسوند ندارد**. اگر با Notepad بسازند، `.gitignore.txt` می‌شود.
- اگر روی پوشه‌ی `venv` کلیک کرده بودند، فایل داخل venv ساخته می‌شود و کار نمی‌کند.

محتوا، فقط دو خط:

```
venv/
__pycache__/
```

دلیل هر خط را **بپرسید، نگویید** (فایل `live-code/gitignore-sample.txt` برای خودتان).

```bat
git status
```

پوشه‌ی venv **ناپدید شد**. 🎉 بگذارید این را ببینند.

```bat
git add .
git status
git commit -m "Add colored quiz with 5 questions"
git log --oneline
```

**🚨 تله‌ی ویندوزی — قبل از زدن `git log` بگویید:** خروجی در یک صفحه‌ی مخصوص باز می‌شود
که **با کلید `q` بسته می‌شود**. اگر نگویید، نصف کلاس فکر می‌کند ترمینال هنگ کرده.

**⚠️ پیام `LF will be replaced by CRLF`:** عادی است، خطا نیست. یک جمله:
«ویندوز و بقیه‌ی دنیا سر پایان خط توافق ندارند؛ git خودش ترجمه می‌کند.»

# ۶۲ تا ۷۴ — 🎉 سفر در زمان

## دقیقه‌ی ۶۲ تا ۶۸ — restore

انتقام فاجعه‌ی دقیقه‌ی ۳۲:

> «حالا بازی‌تان را **عمداً خراب کنید**. هرچه دلتان می‌خواهد. چند خط پاک کنید، وسطش
> چرت‌وپرت بنویسید. اجرا کنید — باید خراب باشد.»

بگذارید واقعاً خرابش کنند (بچه‌ها عاشق این قسمت‌اند). بعد:

```bat
git status
git restore game.py
```

فایل را ببینند: **سالم برگشته.**

> «همان کاری که نیم ساعت پیش با Ctrl+Z نتوانستید بکنید، حالا با یک دستور شد.
> و مهم‌تر: **مهم نیست فایل را بسته باشی، کامپیوتر را خاموش کرده باشی، یا یک هفته
> گذشته باشد.** آلبوم یادش می‌ماند.»

## دقیقه‌ی ۶۸ تا ۷۴ — و حالا VS Code تغییرها را نشانتان می‌دهد

**این بخش دو نیمه‌ی جلسه را به هم می‌بندد.** یک تغییر کوچک بدهند (مثلاً یک پیام را عوض کنند)
و به VS Code نگاه کنند:

- **نوار باریک کنار شماره‌ی خط**: خط آبی = عوض شده · سبز = جدید · مثلث قرمز = پاک شده
- اسم فایل در نوار کنار **زرد** می‌شود با حرف `M` (یعنی Modified)
- آیکون **Source Control** (سومی در نوار کنار) → روی نام فایل کلیک کنند →
  **نمای دو ستونه**: چپ نسخه‌ی commit شده، راست نسخه‌ی فعلی

> «`git status` به شما **می‌گوید** چه چیزی عوض شده. VS Code **نشانتان می‌دهد**.
> ما دستورها را تایپ می‌کنیم چون می‌خواهیم بفهمیم زیر دکمه‌ها چه می‌گذرد —
> ولی برای *دیدن* تغییرها، این پنجره بهترین دوست شماست.»

⛔ **دکمه‌های Commit و Stage در آن پنل را امروز نزنید.** فقط نگاه‌کردن.

# ۷۴ تا ۸۲ — پیام commit + سه commit تمرینی

**قرارداد پیام (۲ دقیقه، روی تخته):**

- ✅ `Add start menu` · ✅ `Fix score not resetting`
- ❌ `تغییرات` · ❌ `final2` · ❌ `asdfgh`

> «فعل امری + چه چیزی + کوتاه. پیام commit را برای **خودتِ سه ماه بعد** می‌نویسی.»

**تمرین (۶ دقیقه):** سه تغییر کوچک، سه commit جدا. مثلاً:
1. یک سؤال جدید اضافه کنید → commit
2. رنگ یک پیام را عوض کنید → commit
3. متن پیام پایانی را بهتر کنید → commit

بعد `git log --oneline` هر تیم را روی پرده مرور کنید و **پیام‌ها را بلند نقد کنید**.
بهترین پیام کلاس را تحسین کنید.

**⚠️ نکته‌ی مربی — به بچه‌ها یاد ندهید:** `git reset --hard`.
خطرناک‌ترین ابزار git را دست تازه‌کار ندهید. اگر کسی از اینترنت پیدایش کرد، بگویید
«هست، ولی دو جلسه‌ی دیگر.»

# 🪜 نردبان حذف

1. ~~دور ۳ مسابقه‌ی راه‌اندازی~~ (۴ دقیقه)
2. ~~نمای دو ستونه‌ی Source Control~~ — فقط نوار رنگی کنار شماره‌ی خط را نشان بدهید (۴ دقیقه)
