قبل از هر چیز — چیزی که الان داری
یک محصول. نه یک تمرین. یک فایل اجرایی که به هر کسی بدهی، کار می‌کند؛ با داده‌ی قابل‌ویرایش، رده‌بندی ماندگار، ۲۵ تست خودکار، و کدی که وقتی چیزی خراب می‌شود پیام آدمیزاد می‌دهد.
و روی GitHub است — اولین چیز واقعی تو روی اینترنت. سه سال دیگر که برای کارآموزی جایی می‌روی، همین لینک را نشان می‌دهی.

🎯 سه مسیر — یکی را انتخاب کن

کسی که هر هفته یک زبان عوض می‌کند، هیچ‌کدام را یاد نمی‌گیرد. یکی را انتخاب کن و سی روز رویش بمان.
۱️⃣ همین بازی را بزرگ‌تر کن — کم‌ریسک‌ترین
چیزی تازه یاد نمی‌گیری، ولی همه‌چیزِ این دوره را محکم می‌کنی. اگر مطمئن نیستی کدام مسیر، از اینجا شروع کن.
  • بازی سه‌نفره کن — self._players یک لیست است، چقدر سخت است؟
  • قدرت ویژه‌ی تازه: 🛡️ سپر، ⏱️ زمان اضافه، 🔄 تعویض سؤال
  • حالت تک‌نفره در برابر کامپیوتر
  • دسته‌بندی: «فقط سؤال‌های علوم»
  • برای هر کدام، اول تست بنویس — عادتی که یاد گرفتی
۲️⃣ گرافیک و بازی‌سازی — pygame
بازی از ترمینال بیرون می‌آید: پنجره، تصویر، صدا، موشواره.
  • pip install pygame و اولین پنجره‌ات را باز کن
  • ⭐ و اینجا سودِ قانون ۴ را می‌بینی: engine.py هیچ print و input ندارد — پس دست‌نخورده می‌ماند و فقط «دهان» را عوض می‌کنی. همان بازی، با صورت تازه.
  • بعدش: Flappy Bird، مار، یا یک بازی پلتفرمر ساده
۳️⃣ وب — Flask، بعد HTML و CSS
بازی روی اینترنت، و دوستت از گوشی‌اش بازی می‌کند.
  • pip install flask — با ۱۵ خط، اولین صفحه‌ی وبت بالا می‌آید
  • باز هم engine.py دست‌نخورده می‌ماند
  • و questions.json؟ دقیقاً همان قالبی است که سرورها رد و بدل می‌کنند
  • بعدش HTML و CSS، و بعد JavaScript
و یک مسیر چهارم که مال همه است: اتوماسیون
هر کارِ تکراری و حوصله‌سربری که با کامپیوتر می‌کنی، احتمالاً پایتون می‌تواند جایت انجامش بدهد: مرتب‌کردن فایل‌ها، تغییر نام دسته‌جمعی عکس‌ها، خلاصه‌کردن یک فایل اکسل. کتاب Automate the Boring Stuff with Python رایگان آنلاین است.

🧰 چیزهایی که نیمه‌تمام ماند

وقت نشد بگوییم، ولی وجود دارند. وقتی لازمشان شدی، سراغشان برو:
موضوعکِی لازمت می‌شود
git branch و merge وقتی با یک نفر دیگر روی یک پروژه کار کنی. «خط زمانی موازی»: کار نیمه‌کاره جایی جز main انجام می‌شود
Pull Request و کد ریویو همان‌جا — قبل از اینکه کدت وارد پروژه شود، یکی نگاهش می‌کند
git revert وقتی یک commit خراب را باید خنثی کنی (پاک نمی‌شود، خنثی می‌شود)
پایگاه داده (sqlite3) وقتی JSON برای حجم داده‌ات کم بیاورد
مانیتورینگ (Sentry) وقتی برنامه‌ات روی کامپیوترِ صد نفرِ دیگر است و لاگ دستِ تو نیست

🧭 سه عادت که تفاوت را می‌سازند

  1. خطا را بخوان. ۹۰٪ وقت‌ها جواب داخل همان متن قرمز است — از پایین به بالا. این را از جلسه‌ی ۳ بلدی.
  2. انگلیسی سرچ کن. «python list index out of range» جواب دارد؛ فارسی‌اش معمولاً نه. انگلیسیِ فنی را از همین سرچ‌ها یاد می‌گیری.
  3. کدِ دیگران را بخوان. روی GitHub یک پروژه‌ی کوچک پیدا کن و بخوانش. مثل زبان است: فقط حرف‌زدن کافی نیست، باید بخوانی هم.
