# Quiz Battle ⚔️

بازی مسابقه‌ای **دونفره پشت یک کیبورد** در ترمینال. دو بازیکن به یک سؤال جواب می‌دهند،
سریع‌تر بونوس می‌گیرد، بعضی سؤال‌ها قدرت ویژه دارند — و بعد از ۵ راند، برنده مشخص می‌شود.

> این **نسخه‌ی مرجع مربی** است: همان چیزی که در جلسه‌ی ۱ به بچه‌ها نشان می‌دهید و
> می‌گویید «تا آخر دوره، خودتان این را از صفر می‌سازید».

---

## اجرا در ۳۰ ثانیه

پروژه از قبل یک محیط مجازی آماده دارد؛ فقط اجرا کنید:

```bash
./venv/bin/python main.py --demo
```

اگر می‌خواهید از صفر راه بیندازید:

```bash
python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt && python main.py
```

| دستور | چه می‌کند |
|---|---|
| `python main.py` | بازی معمولی — سؤال‌ها تصادفی از بانک انتخاب می‌شوند |
| `python main.py --demo` | مسابقه‌ی از پیش‌چیده‌شده برای دمو (هر سه قدرت ویژه دیده می‌شود) |
| `pytest -q` | اجرای ۲۹ تست موتور، بانک سؤال و رده‌بندی |

⚠️ **حتماً قبل از کلاس یک‌بار روی همان لپ‌تاپ و پروژکتور تست کنید.** ترمینال‌ها در نمایش
متن راست‌چین فارسی یکسان نیستند؛ روی macOS، iTerm2 و Terminal نتیجه‌ی خوبی می‌دهند.
فونت ترمینال را هم بزرگ کنید تا از ته کلاس دیده شود.

## قوانین بازی (۵ قانون محصول)

1. هر راند، **هر دو بازیکن به همان سؤال** جواب می‌دهند؛ نتیجه بعد از جواب هر دو اعلام می‌شود
   (تا نفر دوم از جواب نفر اول سرنخ نگیرد — بین دو نوبت صفحه پاک می‌شود).
2. جواب درست = **۱۰ امتیاز**. بین درست‌جواب‌ها، سریع‌تر **+۳** بونوس سرعت می‌گیرد.
3. حدود **یکی از هر سه سؤال** یک قدرت ویژه دارد.
4. هر مسابقه دقیقاً **۵ راند**؛ هر جواب **۳۰ ثانیه** مهلت — دیرتر یعنی صفر.
5. بعد از راند پنجم برنده اعلام می‌شود. **فقط رده‌بندی کل** بین اجراها ذخیره می‌ماند.

### قدرت‌های ویژه

| | نام | چه می‌کند |
|---|---|---|
| ⚡ | دوبل | امتیاز کل راند (شامل بونوس سرعت) دو برابر می‌شود |
| 🎯 | سرقت | هر جواب درست، ۵ امتیاز از حریف کم می‌کند — هرگز زیر صفر |
| 🛡️ | سپر | جواب درست یک سپر می‌گیرد که جلوی سرقتِ بعدی را می‌گیرد |

🛡️ سپر، **قابلیت امضای همین نسخه** است. هر تیم در جلسه‌ی ۱ قابلیت امضای خودش را
انتخاب می‌کند (وقت اضافه، تعویض سؤال، سؤال طلایی، مرگ ناگهانی، …).

### دو تصمیم محصولی که عمداً باز گذاشته شده‌اند

اینها را در کلاس **به بحث بگذارید**؛ در جلسه‌ی ۷ هر تیم تصمیمش را با تست سند می‌کند:

- **دوبل + بونوس سرعت:** این نسخه `(۱۰ + ۳) × ۲ = ۲۶` حساب می‌کند، نه `۱۰ × ۲ + ۳`.
- **سرقت وقتی هر دو درست جواب داده‌اند:** این نسخه می‌گذارد هر دو از هم بدزدند. منصفانه است؟

## ساختار پروژه

```
quiz-battle/
├── main.py              ← فقط راه‌اندازی: لاگ، منو، حلقه‌ی بازی
├── config.py            ← همه‌ی ثابت‌ها و مسیرها، یک‌جا
├── game/                ← 🧠 مغز — بدون هیچ print و input
│   ├── question.py      ← یک سؤال و اعتبارسنجی‌اش
│   ├── question_bank.py ← خواندن بانک از JSON و انتخاب سؤال هر مسابقه
│   └── match.py         ← موتور بازی: امتیاز، بونوس سرعت، قدرت‌های ویژه، برنده
├── ui/console.py        ← 👄 دهان — تنها جای print/input/رنگ/کرنومتر
├── storage/scoreboard.py← 💾 حافظه — رده‌بندی ماندگار
├── questions.json       ← بانک ۳۰ سؤالی (محتوای محصول است، در git می‌ماند)
└── tests/               ← ۲۹ تست
```

**دو قانون معماری که کل دوره روی آنها سوار است:**

- موتور بازی `print` و `input` ندارد. هرگز.
- موتور هیچ‌وقت `time.time()` صدا نمی‌زند؛ زمان از بیرون **تزریق** می‌شود.
  به همین دلیل تست «جواب ۳۱ ثانیه‌ای» صفر ثانیه طول می‌کشد، نه ۳۱ ثانیه.

## افزودن سؤال به بانک

فایل `questions.json` را باز کنید و یک شیء تازه اضافه کنید — نیازی به دست‌زدن به کد نیست:

```json
{
  "text": "پایتخت ژاپن کدام است؟",
  "options": ["توکیو", "کیوتو", "اوساکا", "سئول"],
  "correct": "A",
  "power_up": null,
  "category": "geography"
}
```

- `options` باید دقیقاً **۴** گزینه باشد، به ترتیب A تا D.
- `correct` یکی از `"A"`, `"B"`, `"C"`, `"D"`.
- `power_up`: `null` یا `"double"` یا `"steal"` یا `"shield"`.

اگر سؤالی قالب درست نداشته باشد، بازی هنگام شروع با **شماره‌ی همان سؤال** خطا می‌دهد.
