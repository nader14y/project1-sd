# ساخت و انتشار بازی روی GitHub Pages

آدرس بازی: [کوییز بتل](https://nader14y.github.io/project1-sd/)

GitHub Pages فایل‌های ایستا را منتشر می‌کند و سرور Flask را اجرا نمی‌کند. نسخهٔ Pages با Pyodide پایتون را در مرورگر اجرا می‌کند و همان قوانین و مدیریت نوبت نسخهٔ سرور را به کار می‌گیرد. `engine.py`، `storage.py` و `web_game.py` بدون تبدیل به جاوااسکریپت در خروجی ساخت کپی می‌شوند. نسخهٔ Flask نیز با `python web.py` قابل اجراست.

## فایل‌های مرتبط

| فایل | مسئولیت |
|---|---|
| `scripts/build_pages.py` | رندر قالب به HTML ایستا و کپی فایل‌های مورد نیاز به `dist/pages` |
| `static/pages-bridge.js` | دریافت Pyodide و ماژول‌ها، اجرای درخواست‌ها در مرورگر و ذخیرهٔ وضعیت |
| `pages_runtime.py` | تطبیق درخواست‌های رابط با `GameStore` و اعتبارسنجی و بازیابی وضعیت JSON |
| `static/app.js` | رابط مشترک؛ اگر رابط محلی موجود باشد از آن استفاده می‌کند و در نسخهٔ Flask درخواست HTTP می‌فرستد |
| `.github/workflows/pages.yml` | اجرای تست‌ها، ساخت و انتشار خودکار سایت |
| `tests/test_pages.py` | تست ساخت، حفظ موتور، ادامهٔ بازی، پایان زمان، امتیازدهی و دادهٔ خراب |

## اجرای بازی در مرورگر

قالب منتشرشده ابتدا `pages-bridge.js` و سپس `app.js` را بارگذاری می‌کند. پل مرورگر تابع `window.quizLocalRequest` را می‌سازد. تابع `request` رابط کاربری، به‌جای ارسال درخواست به `/api/`، این تابع را صدا می‌زند.

در اولین فراخوانی، Pyodide نسخهٔ ثابت `314.0.7` از `cdn.jsdelivr.net` دریافت می‌شود. ماژول‌های پایتون و بانک سؤال از همان سایت دریافت و در فایل‌سیستم حافظه‌ای Pyodide قرار می‌گیرند. سپس نمونهٔ `BrowserRuntime` ساخته می‌شود. اگر دریافت محیط اجرا ناموفق باشد، پیام فارسی و دکمهٔ تلاش دوباره نمایش داده می‌شود.

شکل مسیرها، دادهٔ ورودی و وضعیت بازی با نسخهٔ Flask هماهنگ است، اما `/api/` در Pages مسیر HTTP واقعی نیست. کوکی نشست، CSRF سمت سرور و لاگ درخواست HTTP نسخهٔ Flask در این نسخه اجرا نمی‌شوند. مقدار `browser-local` در فیلد `csrf_token` فقط برای سازگاری رابط مشترک است و نقش امنیتی ندارد.

## نگهداری داده

کلید `quiz-battle:pages:v1` در `localStorage` وضعیت یک بازی و جدول امتیازهای همان مبدأ سایت را نگه می‌دارد. هر checkpoint شامل نسخهٔ قالب، جدول امتیازها، سؤال‌های انتخاب‌شده، امتیاز فعلی، پاسخ‌های ثبت‌شده، زمان شروع نوبت و نوبت‌های تمام‌شده است.

پیش از هر عملیات، وضعیت ذخیره‌شده اعتبارسنجی و بازیابی می‌شود و پس از عملیات در یک رشتهٔ JSON ذخیره می‌شود. داده با JSON خوانده می‌شود و به‌عنوان کد اجرا نمی‌شود. این فرایند امکان ادامهٔ بازی پس از تازه‌سازی و جلوگیری از ثبت دوبارهٔ امتیاز نتیجهٔ نهایی را فراهم می‌کند.

دادهٔ کاملاً خراب با هشدار کنار گذاشته می‌شود. اگر فقط وضعیت بازی خراب باشد، جدول امتیاز معتبر حفظ می‌شود و بازی تازه قابل شروع است. اگر مرورگر اجازهٔ نوشتن ندهد یا فضای آن پر باشد، وضعیت در حافظهٔ همان تب باقی می‌ماند و هشدار ذخیره‌نشدن نمایش داده می‌شود.

در مرورگرهای دارای Web Locks، عملیات تب‌های یک مبدأ با قفل مشترک اجرا می‌شوند. در مرورگرهای قدیمی فاقد این امکان، درخواست‌های هر تب به‌ترتیب اجرا می‌شوند؛ برای جلوگیری از تداخل، بازی را فقط در یک تب انجام دهید. پاک‌کردن داده‌های سایت یا استفاده از حالت خصوصی می‌تواند نتیجه‌های ذخیره‌شده را حذف کند.

زمان با ساعت محلی مرورگر محاسبه می‌شود تا زمان شروع نوبت میان بارگذاری‌های مجدد قابل بازیابی باشد. بستن تب یا پنهان‌کردن صفحه زمان را متوقف نمی‌کند؛ پایان زمان در دسترسی بعدی به وضعیت بازی اعمال می‌شود. این نسخه برای رقابت دوستانهٔ محلی است؛ داده و ساعت مرورگر قابل دست‌کاری‌اند و پاسخ‌های صحیح از ابزارهای توسعه قابل مشاهده‌اند. امتیازها بین کاربران یا دستگاه‌ها همگام نمی‌شوند.

## ساخت و بررسی محلی

از پوشهٔ اصلی پروژه اجرا کنید:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/build_pages.py
python -m http.server 8001 --directory dist
```

سپس [پیش‌نمایش محلی](http://127.0.0.1:8001/pages/) را باز کنید. برای دریافت Pyodide به اینترنت نیاز است. فایل را مستقیم با `file://` باز نکنید؛ ماژول‌ها با `fetch` دریافت می‌شوند. برای بررسی دریافت اولیه، شروع بازی، پاسخ دو بازیکن، تازه‌سازی در حین نوبت و پایان مسابقه را امتحان کنید.

ساخت از مسیرهای نسبی استفاده می‌کند تا زیر مسیر `/project1-sd/` نیز کار کند. فقط فایل‌های بازی در خروجی کپی می‌شوند؛ `.git`، محیط مجازی، لاگ‌ها و جدول امتیاز نسخهٔ سرور در خروجی قرار نمی‌گیرند. پوشهٔ خروجی در Git نادیده گرفته می‌شود و GitHub Actions آن را به‌صورت artifact منتشر می‌کند.

## انتشار خودکار

در تنظیمات مخزن، مسیر **Settings → Pages → Build and deployment → Source** باید روی **GitHub Actions** باشد. workflow با push به `main` یا اجرای دستی `workflow_dispatch` آغاز می‌شود.

۱. job ساخت، پایتون ۳٫۱۴ و وابستگی‌ها را نصب می‌کند.
۲. همهٔ تست‌ها را اجرا می‌کند؛ شکست تست مانع انتشار می‌شود.
۳. خروجی `dist/pages` را می‌سازد و با `upload-pages-artifact` بارگذاری می‌کند.
۴. job انتشار با دسترسی‌های `pages: write` و `id-token: write` سایت را در محیط `github-pages` منتشر می‌کند.

کلید یا توکن شخصی در فایل‌های پروژه قرار نمی‌گیرد؛ workflow از دسترسی خود GitHub Actions استفاده می‌کند. وضعیت هر انتشار در تب Actions مخزن قابل مشاهده است. تغییر کدهای `web.py` همچنان مربوط به اجرای Flask است؛ برای تغییر رفتار مشترک بازی، `engine.py` و `web_game.py` منبع منطق‌اند.

## لاگ و رفع خطا

لاگ‌های دریافت محیط پایتون، اجرای محلی، ذخیره‌سازی و رویدادهای بازی در کنسول مرورگر دیده می‌شوند و به فایل لاگ سرور فرستاده نمی‌شوند. خطای ساخت یا انتشار در GitHub Actions ثبت می‌شود. نسخهٔ Flask همچنان لاگ جداگانهٔ `quiz_web.log` دارد.

| مشکل | بررسی |
|---|---|
| دریافت اولیه انجام نمی‌شود | دسترسی به `cdn.jsdelivr.net` و خطاهای Network یا Console مرورگر را بررسی کنید |
| صفحهٔ سایت ۴۰۴ است | موفقیت job انتشار، تنظیم Source و آدرس دارای `/project1-sd/` را بررسی کنید |
| دکمه‌ها یا فایل‌ها بارگذاری نمی‌شوند | خروجی build و مسیرهای نسبی فایل‌های static را بررسی کنید |
| ذخیره‌سازی هشدار می‌دهد | مجوز ذخیرهٔ دادهٔ سایت، حالت خصوصی و فضای مرورگر را بررسی کنید |
| نسخهٔ تازه دیده نمی‌شود | تکمیل انتشار آخرین commit را بررسی و سپس صفحه را تازه‌سازی کنید |
